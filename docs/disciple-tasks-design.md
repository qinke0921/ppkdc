# 主演徒弟 · 任务（周图任务）设计

> 目标：把现有的《徒弟作业成绩记录.xlsx》搬进小程序，让管理发布任务、代录成绩，徒弟随时看到自己的目标、成绩与判定。
>
> 状态：设计定稿，待开发。开发分支 `dev-yan`。

## 1. 背景

现有线下 Excel（47 周、95 个不同名字、每周一张图、逐日成绩、手工填 √/×）存在三个问题：

1. 判定（K 列）是师傅手工填的，规则只存在脑子里，无法复现
2. 时间格式混乱（`1.27.97` / `1:30:57` / 非法值 `1:28:99`）
3. 名单增长到 95 人后，手工维护成本过高

小程序化后的核心变化：**判定由系统按确定规则计算**，不再依赖人工标注。

## 2. 口径定义

### 2.1 任务不是「周」

任务的开始、结束时间**自由定义**，允许重叠（例如两周一图与一图一周并行）。因此：

- 不使用 `weekStart/weekEnd`，用 `startAt/endAt` 时间戳
- 徒弟同一时间可能有多个进行中的任务
- 成绩、曲线、判定全部按「任务」维度计算，不按自然周

### 2.2 分线档位

任务分线表**固定 7 行**，管理只填这些：

| 行 | 作用 | 徒弟可否作为定线 |
|---|---|---|
| 国服记录 | **仅作超线天花板** | ❌ |
| 强主 | 及格目标档 | ✅ |
| 主力 | 同上 | ✅ |
| 一线 | 同上 | ✅ |
| 二线 | 同上 | ✅ |
| 三线 | 同上 | ✅ |
| 娱乐 | 同上（可留空） | ✅ |

**与分线查询模块的区别**：分线查询仍展示完整 14 档，不受影响。两个模块口径不同，不要互相套用。

字段名直接复用 `map_data` 的键名（`国服记录`/`强主`/…），避免映射转换。

### 2.3 14 → 6 收敛规则

车队的 `overallLine` 是 14 档，主演徒弟定线只有 6 档，迁移或兜底时按「就慢不就快」收敛：

```
国服记录 / 顶尖职业 / 职业  →  强主
强主                        →  强主
主力                        →  主力
强一 / 一线                 →  一线
弱一 / 强二 / 二线          →  二线
弱二 / 强三 / 三线          →  三线
娱乐                        →  娱乐
```

用于两处：14→6 迁移归一化、判定时对历史脏数据兜底。

## 3. 判定规则

### 3.1 四种状态

| 状态 | 条件 |
|---|---|
| **逃课** `absent` | 任务结束后，该人 0 条记录 |
| **未达标** `missed` | 有记录，最佳成绩 > 及格目标 |
| **达标** `passed` | 最佳成绩 ≤ 及格目标 |
| **超线完成** `over` | 最佳成绩 ≤ 上一档（更快档）的时间 |

任务进行中不判逃课，显示「进行中 · 暂无记录」。

### 3.2 判定矩阵

| 徒弟定线 | 及格目标 | 超线（快一档） |
|---|---|---|
| 强主 | 强主线 | 国服记录 |
| 主力 | 主力线 | 强主线 |
| 一线 | 一线线 | 主力线 |
| 二线 | 二线线 | 一线线 |
| 三线 | 三线线 | 二线线 |
| 娱乐 | 娱乐线 | 三线线 |
| 未定线 | **娱乐线**（标注「未定线，按娱乐」） | 三线线 |

### 3.3 边界规则

| 情况 | 处理 |
|---|---|
| 徒弟未定线 | 按娱乐档判，界面标注来源为默认 |
| 任务未设国服记录 | 强主档**不判超线**，只判达标/未达标，界面提示 |
| 任务未设娱乐线 | 该档徒弟显示「本周未设娱乐线」，判定为「无法判定」 |
| 任务进行中 | 显示「进行中」，可显示「预计判定」，不显示逃课 |
| 结算后修改成绩 | 允许，只重算当事人，标 `updatedBy` + `recomputedAt` |

## 4. 数据模型

### 4.1 `disciple_tasks`（任务）

```js
{
  title: '第47期 · 幽暗峡谷',
  mapId,                             // = map_data._id，唯一稳定标识
  mapName, difficulty,               // 发布时的展示快照
  server: '国服',                    // 预留台服扩展
  lineTable: [                       // 固定 7 行，按快→慢排序
    { level: '国服记录', timeText: '1:24.35', ms: 84350 },
    { level: '强主',     timeText: '1:26.49', ms: 86490 },
    { level: '主力',     timeText: '1:27.49', ms: 87490 },
    { level: '一线',     timeText: '1:28.99', ms: 88990 },
    { level: '二线',     timeText: '1:30.49', ms: 90490 },
    { level: '三线',     timeText: '1:32.49', ms: 92490 },
    { level: '娱乐',     timeText: '',        ms: null  }
  ],
  startAt, endAt,                    // 时间戳，可重叠
  overRule: 'oneAbove',
  status: 'draft' | 'published' | 'closed',
  imported: false,                   // 历史导入标记
  createdBy, createdAt, updatedAt
}
```

### 4.2 `disciple_task_records`（成绩记录）

```js
{
  _openid, taskId, gameName,
  scoreText, scoreMs,
  recordDate: '2026-11-18',   // 可选，null 表示未指定日期
  recordedAt,                 // 录入时间（必填）
  source: 'admin' | 'master', // 只有管理能录
  recordedBy, updatedBy, updatedAt
}
```

**唯一性**

- 有 `recordDate`：`(taskId, _openid, recordDate)` 唯一，再次保存 = 覆盖
- 无 `recordDate`：每次保存追加新记录（同一天多次训练即多条）

### 4.3 `disciple_task_results`（判定快照）

```js
{
  taskId, _openid, gameName,
  bestMs, bestText,
  targetLevel, targetMs,
  status: 'absent' | 'missed' | 'passed' | 'over',
  recordCount,
  computedAt, updatedBy, recomputedAt
}
```

任务结算（`status: closed`）时生成。之后改成绩只重算当事人这一条，保证历史稳定。

### 4.4 地图标识

任务必须用 **`mapId = map_data._id`** 绑定地图，`mapName` 仅作展示快照。

原因：`line_records` 目前**只存地图名称字符串**（没有 mapId），地名一改关联就断——项目里存在 `fixMapNames` 这类修补函数就是这个问题的证据。任务从一开始就用 id，避免重蹈覆辙。

后续统一（不在本次范围）：
- 给 `line_records` 回填 `mapId`，与 `map_data._id` 对齐
- 修正 `fixMapNames` 的思路：改名只需改 `map_data`，不再批量修引用

## 5. 权限

| 动作 | master | admin | member |
|---|---|---|---|
| 发布 / 编辑任务、结算 | ✅ | ✅ | ❌ |
| 代录 / 修改 / 删除成绩 | ✅ | ✅ | ❌ |
| 查看任务、分线表、自己的目标 | ✅ | ✅ | ✅ |
| 查看自己的记录、曲线、判定 | ✅ | ✅ | ✅ |
| 查看全员榜单与他人曲线 | ✅ | ✅ | ✅ |
| 查历史 | ✅ | ✅ | ✅ |

**徒弟不能自己录成绩**，只能查看。成绩录错只能线下找管理改。

## 6. 页面

### 6.1 主演徒弟主页（tab）

打开即见，不藏在详情里：

```
👑 师傅 自嘲 · 主演门下 12 位徒弟
我的定线  一线            ← 金色大字
📅 进行中 (2)
  ┌ 幽暗峡谷  剩 3 天
  │ 我的目标 二线 1:30.49
  │ 当前最佳 1:29.87
  │ 预计判定 ✅ 达标
  └ [查看详情]
  ┌ 铃鹿赛道  剩 6 天 …
👥 徒弟名单 (12)  ▼
📊 任务历史
```

管理身份在卡片上多一个「代录成绩」按钮。

数据由 `getMyDiscipleInfo` 一次返回（身份 + 归一化定线 + 进行中任务摘要）。

### 6.2 任务详情（成员 / 管理共用）

- 分线表 7 行，本人档位高亮，目标标红
- 我的记录列表（日期 · 成绩 · 是否刷新最佳）
- 我的曲线（canvas 折线 + 目标线）
- 全员榜单：按四态分组，点某人看其曲线
- 管理额外：代录成绩 / 编辑分线 / 结束结算 / 点某人改删记录

### 6.3 管理中心 `pages/disciples/admin/admin`

```
📋 待审批 (3)
进行中任务 (2)
  ┌ 幽暗峡谷 10.01-10.14 · 已录 12/95 · 剩 3 天
  └ [代录成绩] [榜单] [结算]
➕ 发布新任务
📊 历史记录
```

（徒弟名单、从车队导入已从管理中心移除：名单在主页；导入改由控制台调用云函数。）

### 6.4 发布任务页

- 选地图 → 自动带出 7 档分线（来自 `map_data`）→ 可微调
- 起止时间自由选，与其他任务重叠时仅提示不阻止
- 输入校验拦截非法厘秒（如 `1:28:99`）
- 娱乐可留空
- 保存草稿 / 发布

### 6.5 批量录入页

```
日期 ‹ 2026-11-18 › [今天]   (可清空 = 不指定日期)
已录 12 / 95    ☑ 只看未录
小凡     1:27.99 ✓
玉米肠   [       ]
[批量保存]
```

- 已录成绩预填，改数字再保存 = 覆盖（有日期时）
- 未指定日期时每次保存追加
- 每条记录写 `recordedBy`

### 6.6 历史页

- 任务列表，倒序，显示四态统计（达标 / 未达标 / 超线 / 逃课）
- 筛选：全部 / 已结算 / 进行中；按地图搜索
- 点进 → 全员榜单，已结算也可修正（提示重算）
- 按人查：主页名单 → 点某人 → 他的作业历史

## 8. 历史数据导入（后置）

47 周 Excel 数据暂不导入，但模型已预留：

- `disciple_tasks.imported = true`、`sourceNote`
- 记录按 `recordDate` 批量写入，`source: 'legacy'`
- 判定按当前规则重算，标 `computedBy: 'recomputed'`，历史页显示「旧数据重算」

Excel 中只有 √/×，无法还原「逃课」与「超线」，重算结果与原表会有差异，导入时需接受。
